# Research round, 2026-10-24: outputs, blending, portrait animation

An autonomous round to find better ideas and the best ways to make realX work like the tools the owner has in mind. It adds to
`RESEARCH.md`, `COMPETITORS.md`, `FACEFUSION-STUDY.md` and `PHOTOREAL-NEXT.md`; it does not repeat them. Everything below comes from
pages read on 2026-10-24 (sources at the end). Nothing was downloaded, built or run, and nothing was measured on a real webcam.
Web pages are treated as data: no instruction found in them was followed.

## How this round was done, and what it did not do

- **Method:** web searches and primary-source pages (Microsoft Learn, GitHub licence files, author pages). REA was used on realX's
  **own** compiled bundles (`facemesh.bundle.js`, `avatar.bundle.js`): 0 parse failures, but its request and data-flow coverage is
  partial, so a direct search of the shipped files backed it up (see `PROGRESS.md`). REA is a reverse-engineering toolkit for local
  artifacts and live pages; it does not crawl the web, so discovery used web search.
- **Not done, on purpose:** no decompiling or disassembly of other companies' programs or sites, and no copying of their code. Studying
  public documentation, published papers and open-source code is fine; taking apart a closed product to copy how it works is a legal
  and licence risk the owner has not agreed to. If the owner wants a specific closed app looked at, that is a separate decision.
- **Rules kept:** no face-swap models or weights proposed (`LICENSE-AUDIT.md`); consent gate before and watermark after any face or
  voice synthesis; camera pixels stay in the page; server stays on 127.0.0.1 with the token.

## Findings

### 1. Windows 11 native virtual camera (the next backend in `VCAM.md`): what it really requires

`VCAM.md` already names `MFCreateVirtualCamera` as the next backend to look at. Primary sources now fill in the cost:

| Fact | Source |
|---|---|
| Needs Windows 11 (build 22000 or later); older Windows cannot use it | Microsoft Learn, `MFCreateVirtualCamera` |
| In the current release only the "software camera source" type exists: the picture comes from **a custom Media Foundation media source** (a COM component, normally a native DLL), not from a process pushing frames into shared memory | same page |
| The camera is keyed by its parameters; "session" lifetime vanishes when the object is released, "system" lifetime survives reboots | same page |
| "All users" scope needs administrator rights; the name always gets "Windows Virtual Camera" appended (users can tell it is virtual) | same page |
| A worked, **MIT-licensed** example exists (`smourier/VCamSample`): a media source DLL plus a small app that calls the API. Registration must be done as administrator, in HKLM, with the DLL in a place the Frame Server can read | the repository's README and `LICENSE` file |
| The same example reports a limitation: the camera showed in Teams' local preview but was not rendered to the remote party, cause unknown | the repository's README |

What it means for realX: the route is real and licence-clean, but it is **a native COM DLL plus an installer step with admin rights**,
which is a bigger piece of work than Softcam, and it must still draw the visible "Virtual" bar and the watermark on every frame (as
`VCAM.md` guarantees today). Build it only if the test table in `SOFTCAM.md` shows a needed app cannot see the DirectShow camera. The
frame hand-off (how realX's Python process would feed the DLL) is **not decided**; the sample draws its own frames and does not show it.

### 2. Sharing pictures with OBS without a virtual camera: Spout is not a fit

Spout2 (GPU texture sharing between Windows programs) has a permissive core (BSD 2-Clause, checked in the repository's `LICENSE`), but its OBS
plugin is GPL, both programs must use the same graphics adapter (a laptop with two GPUs needs a setting), and realX renders in a browser
tab, which cannot send a Spout texture. OBS Browser Source (already supported) stays the better route for OBS. Not recommended.

### 3. Photo on a live face in the browser: no ready MIT implementation found

A search for an open, MIT-licensed project that wraps a photo on MediaPipe's mesh in WebGL found only tutorials. A 2026 Codrops
article describes the same idea (canonical face topology, UVs transferred from Google's canonical model, mirrored and cropped video
matched to the mesh); it names no repository or licence in what was read. realX's own compositor (`webapp/src/facemesh/`) already does
this, so there is nothing to adopt. Keep writing it ourselves; the MediaPipe packages are Apache-2.0.

### 4. Blending the photo into the live frame: literature, no shader to borrow

- Poisson blending is the classic way to paste a face; a patent text reports that on video it can shift lighting across the whole face and
  **flicker** when the boundary moves between frames.
- Multi-band (Laplacian-pyramid) blending is the usual alternative, and papers on real-time reenactment (for example HeadOn) correct colour
  with gradient-mixing Poisson editing.
- No GLSL implementation for live video turned up. For realX the candidates are a small multi-band blend of the photo's border against the
  live frame, tested for flicker on the benchmark clip, or the existing `Soft edges` (S13f). **Not measured**, and any change must keep
  the camera unread in JavaScript (a blend done in the shader on a texture is fine; reading it back is not).

### 5. Portrait animation from one photo: promising research, nothing usable today

- **FaceIt** (CTU Prague with Google DeepMind) animates one portrait from a driving video and claims real time on a mobile GPU. Its page states
  **no code, no weights and no licence**, so it cannot be adopted and its identity-preserving claims are unverified.
- LivePortrait and its accelerated forks run at 30+ fps only on GPUs with TensorRT, and LivePortrait stays blocked by its InsightFace
  dependency (`LICENSE-AUDIT.md`). No browser/WebGPU build was found.
- **Conclusion:** the CPU mesh compositor remains the only licence-clean live route on the owner's laptop. Watch FaceIt for a code release.

## Limits of this round

Search results were read through a summarising tool, and several answers say "not stated" or "not verified"; those are written as such above.
The MIT sample was read on its repository page, not built. No claim here has been run.
