# Backend audit B4: models, audio, cli, hardware, diag, bench

Branch `audit-backend-b4-modules` (from `photoreal-integration`), 2026-10-21. Read-only audit: no application code and no existing test was changed.
Machine: Intel i5-8365U (4 cores / 8 threads), UHD 620, 7.8 GB RAM (0.6 to 1.3 GB free during the audit), Windows 11, Python 3.12.15.
Note: `docs/audit/AUDIT-2026-10-21.md` named in the brief is not present on this branch, so no cross-reference to it was possible.

## Summary

25 findings: 0 Critical, 0 High, 8 Medium, 12 Low, 5 Info.

The hash-verified download itself is sound: the temp file is created exclusively next to the target, hashed while streaming, size-capped at 64 MB, and only moved into place (`os.replace`) after the SHA-256 matches. A corrupt or swapped file never reaches the models folder, and a blocked model is refused before any file or network access. The weaknesses are around it: one exception class escapes the mirror fallback, `models fetch` returns exit code 0 when everything failed, and the licence gate is label based.

The most practical problems for the owner are on the audio CLI and the diagnostics: `realx voice` shows raw tracebacks on a 24-bit or missing WAV, offline pitch shifting is quadratic in the length of the recording, `realx cohost grant` can save a consent record and then lose its one-time revoke code when the name holds a character the redirected console cannot encode, and the process-memory figure is always empty on Windows.

## Verified OK

- models.py: hash is computed while streaming and compared before `os.replace`; the temp file is created with `mkstemp` in the target folder (exclusive, 0600) and always unlinked in `finally`; the 64 MB cap is enforced before the write; a wrong or truncated body leaves no file behind and does not touch an existing good file; an existing file with a wrong hash is refused (never deleted or overwritten); HTTP 404 on both hosts gives a clear combined message; offline mode is checked twice (`ensure_model` and `_download`) and `REALX_OFFLINE` cannot be bypassed by `download=True`; a real fetch of `yunet` into a temp folder on E took 1.8 s, 232589 bytes, only the final file remained. TLS uses urllib's default verifying context, `http://` start URLs are refused.
- Blocked list: refusal comes before any disk or network access, also with a pre-placed file and `download=True`; unknown or differently-cased names are refused as "unknown model"; `tests/test_model_licenses.py` passes.
- Audio: streaming pitch shifter output is identical whichever way the input is chunked; zero-length input returns zero-length output; NaN input does not poison the state; denormal input costs nothing extra; offline `convert` yields a finite result at -3.0 dBFS peak (measured -3.0001); the provenance mark survives `write_wav` and `read_wav` (extracted `realx|voice`, LSBs preserved); `radio` preset output is time aligned (impulse at 4000 stays at 4000, length preserved); the `pip` preset moves 300 Hz to 400 Hz as designed; PCM16 read is little-endian and float32 in [-1, 1); stereo mixdown drops trailing partial frames; `to_pcm16` clips full scale and 2.0 correctly.
- WAV reader (`read_wav_bytes`): rate bounds, channel limit, duration limit, size limit, zero frames, 24-bit/8-bit/float rejection with a clear message, lying RIFF size.
- cli: `--semitones` out of range, NaN, preset with semitones, unknown preset, bench `--frames 5`, `--resolutions 0x0`, `--fps nan`, `bench-camera --seconds 0` all exit 2 with a one-line message.
- hardware.py: CPU name, 4 cores / 8 threads, RAM total 7.8 GB, UHD 620 and driver version match `Get-CimInstance`; AdapterRAM 1 GB is the real value for this adapter; CUDA is correctly reported unusable; classification rules and the NVIDIA-without-CUDA warning behave as documented; every probe failure is isolated into `notes`. Related tests (`test_hardware.py`, `test_audio.py`, `test_bench.py`, `test_model_licenses.py`) pass.
- diag.py: rings are bounded (120), snapshot maths (linear percentile, `max`, clamping of negative ages) is correct, CPU percentage uses `process_time` over wall time (can exceed 100 with several threads, documented as 100 = one core), clocks are `perf_counter` / `process_time`.
