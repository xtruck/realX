# B3 - Safety audit (consent, watermark, remote, studio)

Date 2026-10-21. Branch `audit-backend-b3-safety` (from `photoreal-integration`). Read-only audit: no application code and no existing test was changed.
Scope: `src/realx/safety/*`, `remote.py`, `studio.py`, the consent routes of `server.py`, plus `pipeline.py`, `stages/builtin.py`, `stages/portrait.py`, `audio/stages.py` and `webapp/src/facemesh/consent.js` where they carry the promise.
Note: `docs/audit/AUDIT-2026-10-21.md` (finding A7, HTTP auth/Host/Origin) does not exist on this branch, so A7 was taken as out of scope and not re-checked.
Method: full read, throw-away reproductions kept in a scratch directory (not committed), existing tests for the scope run (`test_cohost`, `test_remote`, `test_facemesh_consent`, `test_pipeline_strict`, and the consent/watermark/portrait/studio/gate/pipeline tests of `test_portrait`, `test_studio`, `test_core`): 161 passed, 2 skipped. No full suite, no benchmark, no browser.

## 1. Summary

The consent machinery itself is sound: HMAC-SHA256 with domain separation, strict record parsing, constant-time compare, exact scope match, expiry, revocation re-checked on every frame, portrait/photo consent bound to a SHA-256, a fail-closed client when the server is silent or restarted, and a remote adapter that cannot carry pixels.

The weak half of the promise is the **watermark**. It is an LSB mark in 105 pixels of the first row. Every lossy step destroys it (including the product's own MJPEG encoder at quality 82), so does a one-row crop or one `& 0xFE`, and it is forgeable when no key is given (the default everywhere). Also, **no video the server emits today carries a mark or a pixel label**, and `/api/stats` reports `watermark: true` regardless. The one flow that draws a user's photo on a live face (`/facemesh`) is guarded only by JavaScript in the page.

Both gaps are documented in `SAFETY.md` / `FACEMESH.md` as limits. Together they mean the central promise ("gate before, watermark after") holds in the pipeline validator and not in the pixels that leave the machine.

Counts (20 findings): Critical 0, High 2, Medium 6, Low 9, Info 3.

## 3. Watermark robustness

Embedded `realx|portrait|abcd1234` (23 bytes) with and without a 32-byte key into synthetic 640x480 and 1280x720 frames (gradient, shapes, +-6 noise), 5 frames each, then attacked. Value = frames where `extract` returned the exact payload (keyed and unkeyed gave identical results), 640x480 / 1280x720. Small sample (5), but every result is 0 or 5, so the conclusion does not depend on sample size.

| Attack | Detected |
|---|---|
| PNG round trip (lossless) | 5/5, 5/5 |
| JPEG q95 | 0/5, 0/5 |
| JPEG q90 | 0/5, 0/5 |
| JPEG q82 (the server's own MJPEG setting) | 0/5, 0/5 |
| JPEG q70 | 0/5, 0/5 |
| JPEG q50 | 0/5, 0/5 |
| Downscale 50% (and 50% then back up) | 0/5, 0/5 |
| Crop 10% off top/left, or only the top row | 0/5, 0/5 |
| +-1 random noise, or +1 brightness | 0/5, 0/5 |
| Clear the LSB plane (`& 0xFE`) | 0/5, 0/5 |

Other measurements: header bit error rate after JPEG q95 is 48% (random); embedding changes at most 1 level in 105 pixels of row 0; false positives 0/2000 random frames; unkeyed forgery works; a keyed mark copied onto another frame verifies; clearing the LSBs of the first 400 bytes removes it with a max pixel change of 1.

## 5. Verified OK

- Signing: HMAC-SHA256, domain-separated, canonical JSON; key at least 32 bytes and 8 distinct values; `hmac.compare_digest`; non-ASCII signature, NaN expiry, wrong key id and another run's key rejected. Checked by reading, by reproduction, and by `test_facemesh_consent.py` / `test_cohost.py`.
- Scope and subject binding: scope must equal exactly; cohost subject is the slug of the name and `load` re-derives it; `require_consent` checks the gated identity inside the stage. Cross-photo use blocked.
- Face-mesh key: random per run, nothing on disk, a restart invalidates all records.
- Revocation: in-memory set plus a per-frame callback to the vault; tombstone survives restart; an unreadable tombstone counts as revoked; revoke needs a regex-checked record id (no path traversal) and the code.
- Expiry per frame: `ConsentGate.process` and `PortraitAnimate.process` re-verify every frame and `setup` verifies first; `StudioController` degrades on that same frame (read + `test_studio.py`, `test_portrait.py`).
- Attestation strictness: `attested is True` required (1 refused); `hours` finite and in (0, 12]; cohost `days` of 0, negative, NaN, 1e9 rejected.
- Fail-closed: server silent for 6 s ends the photo; 400/403 final; server restart ends the record; a short or empty signing key stops start-up.
- Pipeline ordering: gate before synthesis, label after likeness, no media-altering stage after label or mark, watermark after last synthesising stage (read + tests); the stage tuple is frozen after validation.
- Remote: no pixel path, nothing imports it, https + allowlist + no userinfo/port, credential not stored or logged, request and response bounded.
- Logging: server request log disabled; remote logs host and byte count; `log.py` clips text and states "never log consent contents"; no name, hash or photo was found in any log call in scope.

- Whether the audio mark survives a real `wav_bytes` / WAV player round trip.
- Strength of the `guard.js` label check against a determined page edit (known limit, not tested).
- Rate limiting and body-size limits of the consent routes beyond `MAX_JSON` (A7 area).
- `run_stream` with `workers>1` and revocation in the middle of a batch.
- Anything in the pre-built `src/realx/web/*.bundle.js` that is not in `webapp/src`.
